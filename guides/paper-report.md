# 論文報告簡報指南

適用於 `slides/` 下所有論文報告簡報。製作或修改任何一份論文報告時都遵守本文件；圖形另依 `guides/figures.md`。

## 1. 時間與篇幅

- 一篇論文控制在約 **12 分鐘**：內容頁（不含封面、Outline、章節頁、References）約 12–16 頁，平均每頁 45–60 秒。
- 參考時間分配：

| 段落                                     | 時間     | 頁數   |
| ---------------------------------------- | -------- | ------ |
| Introduction（問題、既有方法的不足）     | 約 2 分  | 2–3    |
| Methodology（想法 → 架構 → 各技術細節）  | 約 5 分  | 5–7    |
| Experiments（設定、主結果、消融、視覺化）| 約 3 分  | 3–4    |
| Conclusion / Discussion                  | 約 2 分  | 3–4    |

## 2. 必備內容

| 內容                                      | 說明                                                                                     | 誰寫          |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- | ------------- |
| 要解決的問題                              | 任務定義、既有方法的不足                                                                 | 依論文整理    |
| 關鍵技術組合                              | 為何這些技術組合起來能解決問題：核心想法，以及整體演算法（訓練與推論流程）               | 依論文整理    |
| 具體改善的技術                            | 每個技術各一頁：它改善了什麼、怎麼做，盡量配圖解；公式只放最關鍵的一兩條                 | 依論文整理    |
| 實驗證據                                  | 設定、主結果、消融（各技術的貢獻）、視覺化                                               | 依論文整理    |
| 為什麼挑這篇（Why This Paper）            | 預留頁面                                                                                 | 報告者自己寫  |
| 作者的結論                                | 貢獻與限制                                                                               | 依論文整理    |
| 自己的結論（My Takeaways）                | 預留頁面                                                                                 | 報告者自己寫  |
| 與自身研究領域的重疊（Overlap with My Research） | 預留頁面                                                                          | 報告者自己寫  |

### 預留頁面格式

報告者要自己寫的頁面，一律用以下格式預留，方便 `grep -n TODO slides/<id>/main.typ` 找出：

```typ
#slide[Why This Paper][
  #callout(title: [TODO], kind: "warn")[To be written by the presenter.]
]
```

除了標題外不要替報告者寫任何內容；可以在對話中提供想法供參考。

## 3. 順序：先大方向，再細節

1. **Introduction**：任務是什麼 → 既有方法卡在哪裡（列出要解決的問題）。
2. **Methodology**：
   1. Problem Formulation（輸入、輸出、目標，簡短）
   2. Key Idea：一句話說明核心想法，以及它和既有作法的關鍵差異
   3. Framework Overview：整體架構圖（可用論文原圖）
   4. 各技術各一頁，順序跟資料流一致；每頁開頭先說「它解決哪個問題」
   5. Training & Inference：整體演算法 / 目標函數
3. **Experiments**：Setup → Main Results → Ablation → Visualization（選用）。
4. **Conclusion**：Paper Summary（作者的結論與限制）→ Why This Paper → My Takeaways → Overlap with My Research。

如果簡報已經有 Introduction，`Why This Paper` 最理想的位置是 Introduction 的最後一頁；由報告者決定是否搬移。

## 4. 文字

- **內文一律英文**。中文只用在封面的報告者姓名等非內文欄位。
- **字要少**：
  - 每頁最多 4–5 個 bullet，每個 bullet 盡量不超過一行（約 10 個英文字）。
  - 寫成關鍵詞片語，不要寫完整句子；不要寫「In this paper, the authors ...」這類開場。
  - 第二層 bullet 只在必要時使用，最多 2–3 個。
  - 能用圖、表、`card`、`flow` 表達的就不要用文字段落。
- 公式：每頁最多 1–2 條關鍵公式；符號在同頁用一個短句說明。
- 數字：一律取自論文原文，表格與圖表標示來源（例如 `(Source: Cai et al. 2025 @cai2025)`）。結果要誠實：方法沒有全面勝出時（例如某個指標輸給 baseline），不要用措辭掩飾。
- 送出前檢查拼字。

## 5. 圖

- 自己畫的圖依 `guides/figures.md`，放在 `slides/<id>/assets/<name>.typ`。
- 論文原圖：從 `docs/papers/<id>.pdf` 以 300 dpi 截取，存成 `slides/<id>/assets/fig-<論文圖號>.png`，並在 caption 註明來源。
- 原圖已經畫好整體架構時，不要重畫；自己畫的圖用來解釋原圖沒講清楚的機制（例如某個模組內部如何運作）。

## 6. 協作規則

- 使用者說明哪些部分已完成或不要修改時，那些部分不做任何更動（包含拼字修正、排版調整）；有建議就在對話中列出。
- 完成後 `just build <id>` 必須成功，並轉成 PNG 逐頁檢查版面：文字不超出頁面、圖不重疊。
- 回報時附上每段的頁數與預估時間，並列出所有 `TODO` 頁面。
